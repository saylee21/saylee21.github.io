Every routing decision was asking Redis about every pod

5,006→22
Redis commands per decision, 5,000 pods

The inflight saturation filter ran before candidate selection, so one request paid a Redis read for each pod in the cluster. I moved it onto the candidate set. p99 at concurrency 32 dropped from 85 to 92 ms to 12.2 to 13.7 ms.

AIBrix · RFC #3552 · 4 PRs merged

A gateway that routed to a pod that no longer existed

110 s→30 s
silent and healthy, now an alert

I cut one gateway replica off from the API server and deleted a pod. It kept the pod in its routing list for 110 seconds and reported healthy. Now every replica checks reachability every 10 s, alerts after 30 s, and exports how old its watch is, at zero extra requests.

I measured before I shipped. An idle watch on Kubernetes 1.29 sent no progress in 300 s, so that metric only turns on for 1.31 and newer.
